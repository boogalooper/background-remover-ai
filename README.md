# Background Remover AI v0.1.6 experimental
> **v0.1.6:** полностью заменён механизм сохранения TIFF. TIFF больше не кодируется через Pillow/libtiff — именно эта ветка могла нативно завершить процесс Windows, оставив нулевой `.tif.tmp`. Теперь используется отдельный безопасный TIFF-writer с ZIP/Deflate-сжатием, проверкой временного файла перед публикацией и автоматическим повтором без сжатия при ошибке. Старый `.tmp` перед записью удаляется. Для TIFF сохраняются ICC, DPI и безопасные базовые поля EXIF; внутренние EXIF/IFD-структуры намеренно не переносятся. Дополнительно создаётся `background_remover_ai_crash.log`: если какая-либо нативная библиотека когда-нибудь снова аварийно завершит процесс, там может остаться диагностический стек.

> **v0.1.4:** управление краем стало понятнее. Сдвиг края теперь явно указан в пикселях итогового полноразмерного файла и допускает диапазон ±100 px. Если результат уже существует и перезапись выключена, программа предупреждает, что новые настройки маски к старому PNG/TIFF не применялись. Проверка существующих результатов выполняется до загрузки модели.

> **v0.1.3:** исправлено сохранение TIFF с альфа-каналом и LZW при наличии EXIF. Служебные указатели исходного JPEG/TIFF больше не переносятся в новый TIFF; если редкое нестандартное EXIF-поле всё же не принимается libtiff, файл автоматически сохраняется без EXIF, но с доступными ICC и DPI.

Локальная программа для **пакетного удаления фона с фотографий** на Windows.

Она рассчитана на простой рабочий процесс: выбрать папку или набор фотографий, выбрать модель и получить готовые изображения с прозрачным фоном и/или отдельные маски. Исходные фотографии программа **не изменяет**.

Первая версия экспериментальная: перед обработкой большой съёмки лучше проверить результат на 5–10 типичных кадрах — особенно волосы, полупрозрачные детали и предметы, близкие по цвету к фону.

## Быстрый старт

1. Распакуйте архив в обычную папку, например `D:\Programs\Background Remover AI`.
2. Один раз запустите **`install.bat`**.
3. После установки запускайте программу через **`run.bat`**.
4. На вкладке **«Быстрый старт»**:
   - выберите папку с фотографиями или отдельные файлы;
   - укажите папку результата;
   - выберите модель;
   - выберите, что сохранить;
   - нажмите **«НАЧАТЬ ОБРАБОТКУ»**.

Программа создаёт собственное окружение Python внутри своей папки. Системный Python и другие программы не изменяются.

## Что выбрать на первом экране

### Исходные фотографии

Можно выбрать:

- одну папку;
- папку вместе со всеми подпапками;
- несколько отдельных файлов.

Поддерживаются `JPG/JPEG`, `PNG`, `TIFF/TIF`, `WebP` и `BMP`.

RAW-файлы камеры (`CR2`, `CR3`, `NEF`, `ARW` и т. п.) в v0.1.6 напрямую не обрабатываются. Для них сначала используйте проявленный JPEG/TIFF.

### Папка результата

Если выбрана одна папка с фотографиями, программа автоматически предлагает подпапку:

`Background Removed`

Опция **«Сохранять структуру подпапок»** полезна для съёмки, разложенной по классам или заказам. Например:

```text
Исходники\1А\IMG_001.jpg
Исходники\2Б\IMG_100.jpg
```

превратятся в:

```text
Background Removed\1А\IMG_001_cutout.png
Background Removed\2Б\IMG_100_cutout.png
```

По умолчанию уже готовые файлы не перезаписываются. Это важно при настройке маски: если `_cutout` уже существует, изменение порогов, гаммы, сдвига или размытия **не изменит старый файл**, пока вы не включите «Перезаписывать готовые файлы» или не выберете новую папку результата. Если при режиме «прозрачный файл + маска» существует только один из двух результатов, программа создаст **только недостающий файл** и не затронет существующий.

## Модели

В программе можно переключаться между тремя вариантами. Модель загружается один раз и затем используется для всей выбранной пачки фотографий.

### BRIA RMBG-2.0 — универсальная

Хороший вариант для первого сравнения. Подходит для людей, предметов и смешанных сцен.

BRIA разрешает локальное использование весов для **некоммерческих задач**. Перед первым использованием нужно один раз получить доступ через Hugging Face:

1. сначала выполните обычный `install.bat`;
2. затем запустите **`setup_bria.bat`**;
3. войдите в Hugging Face в открывшемся браузере и примите условия модели;
4. создайте Read token и вставьте его в окно настройки.

Модель после этого хранится локально в папке программы. При обычной обработке фотографии никуда не отправляются.

### BiRefNet HR Matting — максимум деталей

Более тяжёлый вариант для случаев, где особенно важен край: волосы, мех, мелкие детали, сложный контур. Рабочий размер модели — 2048 px, поэтому она обычно медленнее BRIA, но может дать более аккуратную маску.

Аккаунт Hugging Face для неё не требуется.

### BiRefNet Portrait — люди

Вариант, ориентированный на людей и портреты. Его стоит сравнить с BRIA на ваших типичных фотографиях и оставить тот, который лучше ведёт себя на конкретном фоне и освещении.

### Как выбрать модель на практике

Для первого теста возьмите 10–20 сложных фотографий и прогоните их разными моделями в режиме **«Прозрачный файл + маска»**. Сравнивать удобнее именно маски: сразу видно, потерялись ли волосы, пальцы, элементы одежды или, наоборот, остались куски фона.

Нет необходимости выбирать одну модель навсегда — программа запоминает последний выбранный вариант, а переключение занимает один пункт меню.

## Что сохранять

В поле **«Выход»** есть три режима.

**PNG/TIFF с прозрачностью** — обычный готовый результат без фона.

**Только чёрно-белая маска** — белое означает объект, чёрное фон, серое — частичная прозрачность. Полезно для Photoshop и ручной доработки.

**Прозрачный файл + маска** — создаёт оба варианта. Для первых тестов это самый удобный режим.

### PNG или TIFF

**PNG** — рекомендуемый вариант для большинства задач. Он компактнее и нормально хранит прозрачность.

**TIFF с альфа-каналом** — имеет смысл, если дальнейшая работа строится вокруг TIFF/Photoshop и размер файла не критичен.

Если исходный файл содержит доступный ICC-профиль, EXIF или DPI, программа старается перенести их в прозрачный результат. Отдельная маска метаданные не получает.

Для **TIFF** используется отдельный безопасный writer, не зависящий от системного `libtiff`. По умолчанию TIFF сохраняется с ZIP/Deflate-сжатием; если сжатая запись не удалась, программа автоматически повторяет её без сжатия. До переименования временный TIFF проверяется на ненулевой размер и корректную структуру. ICC-профиль и DPI сохраняются; из EXIF переносятся только безопасные базовые поля (например, производитель/модель камеры, авторские поля). Внутренние EXIF/IFD-указатели, MakerNote и структура исходного контейнера намеренно не копируются — для производного TIFF это безопаснее.

## Настройка края

На первом экране есть три готовых профиля.

### Естественный край — рекомендуется

Используйте его в большинстве случаев. Он почти не вмешивается в маску, которую создала модель.

### Чище фон

Немного сильнее убирает полупрозрачные остатки фона. Может помочь на ровном студийном фоне, но на очень тонких волосах иногда оказывается слишком агрессивным.

### Без дополнительной обработки

Сохраняет маску модели практически как есть. Полезно для сравнения моделей или ручной дальнейшей обработки.

## Вкладка «Расширенные»

Для обычной работы её можно вообще не открывать.

### Маска и край

**Удалять слабый фон ниже** — чем выше число, тем агрессивнее программа очищает слабые остатки фона.

**Считать объектом выше** — влияет на то, насколько быстро уверенные области объекта становятся полностью непрозрачными.

**Гамма маски** — тонкая коррекция перехода между объектом и фоном. `1.0` означает без изменения.

**Сдвиг края маски** — расширяет или сжимает объект после работы нейросети. Значение задаётся **в пикселях итогового полноразмерного файла**: положительное расширяет объект, отрицательное сжимает. На 30–60 Мп фотографии `±2…5 px` почти незаметны; для наглядной проверки попробуйте `+30` и `-30`, а затем подберите меньшее значение.

**Размытие края** — дополнительное смягчение. Для современных моделей обычно лучше оставить `0`.

### Экспериментальное уточнение края

Опция **«Экспериментально уточнять край по исходному изображению»** пытается немного привязать переход маски к деталям полноразмерной фотографии. Она работает уже после нейросети и не заменяет саму модель.

По умолчанию функция выключена. Включать её стоит только если без неё край систематически выглядит слишком грубо. На некоторых фотографиях она может, наоборот, подчеркнуть ненужные детали фона.

Параметр **«Макс. размер уточнения»** ограничивает расход оперативной памяти на больших 40–60 Мп фотографиях.

## Производительность и память

По умолчанию программа настроена консервативно.

### Безопасно ограничивать GPU-пакет

Эту галочку лучше оставить включённой. Она не создаёт несколько копий нейросети в VRAM. Используется **одна модель**, а несколько фотографий по возможности передаются ей одним пакетом.

Для тяжёлой BiRefNet HR безопасный режим автоматически ограничивает пакет одним кадром. Для более лёгких моделей допускается небольшой пакет.

Если вручную выбрать слишком большой пакет и видеопамяти не хватит, программа попытается **автоматически разбить его на меньшие части**, вместо того чтобы сразу завершить всю обработку ошибкой.

### Потоки чтения файлов

Это безопасная параллельность: пока видеокарта обрабатывает текущий кадр, процессор может заранее открыть следующий.

Рекомендуемое начальное значение — **2**. Для быстрых SSD можно попробовать 3–4. Это не создаёт дополнительные копии модели на GPU.

### Буфер предзагрузки

Определяет, сколько следующих фотографий может находиться в оперативной памяти. Для больших файлов обычно достаточно **3**. Увеличение буфера не всегда ускоряет работу, но расходует больше RAM.

### FP16

На NVIDIA лучше оставить включённым: обычно это быстрее и требует меньше VRAM.

## Прогресс и отмена

Программа показывает текущий этап, имя обрабатываемого файла и общий процент.

Кнопка **«Отмена»** не обрывает вычисление видеокарты посередине одного прохода. Она останавливает обработку сразу после завершения текущего GPU-пакета, чтобы не оставлять модель и файлы в неопределённом состоянии.

Уже полностью сохранённые результаты при отмене остаются на месте.

## Что происходит с исходниками

Исходные фотографии **никогда не перезаписываются**.

Результаты записываются в отдельную выбранную папку. Сохранение идёт через временный файл с последующей заменой, чтобы незавершённая запись не выглядела как готовое изображение.

Если входной PNG/TIFF уже имеет прозрачность, новая маска объединяется с существующей альфой, а не делает ранее прозрачные области снова непрозрачными.

## Первый запуск модели

Вес модели не входит в архив приложения. Он скачивается при первом использовании и затем остаётся в `runtime\huggingface`.

Поэтому первый запуск конкретной модели занимает заметно больше времени, чем последующие. Во время загрузки окно может некоторое время оставаться на этапе **«Загрузка модели…»** — после скачивания дальнейшие запуски используют локальный кэш.

Если нужно перенести программу на другой компьютер полностью офлайн, проще сначала один раз скачать нужные модели на компьютере с интернетом, а затем перенести всю папку приложения вместе с `runtime\huggingface`.

## Если что-то пошло не так

### BRIA не запускается

Запустите `setup_bria.bat` и убедитесь, что:

- вы вошли в правильный аккаунт Hugging Face;
- на странице RMBG-2.0 приняты условия доступа;
- использован Read token.

### Ошибка VRAM

Сначала:

1. включите безопасное ограничение GPU-пакета;
2. поставьте **«Кадров за один GPU-проход» = 1**;
3. закройте другие приложения, активно использующие видеокарту.

Не нужно уменьшать количество потоков чтения файлов ради VRAM — они используют в основном оперативную память, а не создают дополнительные модели на видеокарте.

### На волосах остался фон

Попробуйте по порядку:

1. другую модель;
2. профиль **«Естественный край»**;
3. BiRefNet HR Matting;
4. экспериментальное уточнение края;
5. только после этого — небольшую ручную коррекцию порогов.

### Волосы или прозрачная ткань пропадают

Не используйте агрессивный профиль «Чище фон». Вернитесь к «Естественному краю» или «Без дополнительной обработки» и сравните модель.

### Повторный запуск перезаписал бы хорошие результаты

Не включайте **«Перезаписывать готовые файлы»**. При выключенной опции существующие результаты сохраняются; программа делает только то, чего ещё нет.

## Где хранятся настройки и модели

Пользовательские настройки:

`config\ui_state.json`

Скачанные модели и данные Hugging Face:

`runtime\huggingface`

Локальная среда Python:

`runtime\venv`

Лог программы:

`background_remover_ai.log`

Удаление `config\ui_state.json` сбрасывает только сохранённые настройки интерфейса. Кнопка **«Вернуть рекомендуемые значения»** делает это удобнее прямо из программы.

## Что я бы проверил в первую очередь

Для первой реальной проверки возьмите небольшую папку, где есть:

- распущенные волосы;
- светлая одежда на светлом фоне;
- тёмная одежда на тёмном фоне;
- руки и пальцы по краю фигуры;
- мелкие аксессуары;
- один погрудный и один ростовой портрет.

Запустите **BRIA RMBG-2.0** и **BiRefNet HR Matting** с выходом «прозрачный файл + маска», не меняя расширенные настройки. Это быстрее всего покажет, какая модель лучше подходит именно под ваш тип школьной фотографии.

## Если программа запущена из 32-битного Total Commander

Это поддерживается. 32-битный Total Commander может запускать 64-битный Python без ограничений.

Начиная с v0.1.4 установщик проверяет NVIDIA из найденного **64-битного Python 3.11**, а не через обычный поиск `nvidia-smi` в `cmd.exe`. Это важно, потому что Windows может перенаправлять системные каталоги для 32-битного родительского процесса и старая проверка могла ошибочно установить CPU-сборку PyTorch.

Если в нижней строке программы неожиданно написано `устройство: cpu`, хотя в компьютере есть NVIDIA, просто снова запустите новый `install.bat`. Он проверит уже существующее окружение и при необходимости заменит CPU PyTorch на CUDA-версию. В конце установки для NVIDIA должно быть:

```text
CUDA wheel: 12.8
CUDA available: True
GPU: ...
CUDA test OK: ...
```

Принудительный режим `cpu` в расширенных настройках по-прежнему поддерживается. В нём модель всегда переводится в FP32, поэтому сохранённые в FP16 веса BiRefNet не должны приводить к ошибке `Input type (float) and bias type (Half) should be the same`.
